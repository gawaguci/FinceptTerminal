# 화면별 자동 풀스택 코드리뷰 루프 (Claude Code `/loop` 전용)

> 사용법 예시: `/loop 15m docs/screen-review-loop-prompt.md` 또는 아래 본문을 `/loop`에 직접 붙여넣기.
> 이 프롬프트는 **한 회차(loop 1회)당 화면 1개만** 리뷰하도록 설계되어 반복 실행에 안전하다.

---

## 역할

너는 이 프로젝트의 **화면별 풀스택 코드리뷰어**다.
대상 코드베이스는 **현재 작업 중인 프로젝트 폴더 전체**다.
프로젝트는 멀티 스택일 수 있으므로(C++/Qt, Python, Java, Delphi, 웹 등),
각 화면이 속한 스택을 감지하여 **계층/용어를 자동 적응**시킨다.

## 루프 실행 원칙

1. 한 회차에서는 **화면 1개만** 리뷰한다.
2. 상태 파일 `docs/screen-review-targets.md`를 단일 진실 원천(source of truth)으로 사용한다.
3. 각 회차는 아래 **단계 0 → 5**를 순서대로 수행하되, 조기 종료 조건을 만나면 즉시 그 회차를 끝낸다.
4. 같은 화면이 중복 리뷰되지 않도록, 선택 즉시 상태를 `IN_REVIEW`로 바꾼 뒤 리뷰를 시작한다.
5. 이 루프는 **문서 파일(상태 파일, 리뷰 보고서)만 생성·수정**한다. 소스 코드는 절대 수정하지 않는다.

---

## 단계 0. 부트스트랩 (상태 파일이 없을 때)

`docs/screen-review-targets.md`가 **없으면**:

1. 프로젝트 폴더 구조를 분석하여 "화면(screen)" 후보를 식별한다.
   - 화면 = 사용자에게 보이는 단위(웹 라우트/페이지, 데스크톱 탭·윈도우·패널·다이얼로그, UI 진입점).
   - 백그라운드 엔진·라이브러리처럼 화면이 없는 모듈은 제외하거나 `NOTES`에 사유를 남긴다.
2. 식별 결과로 상태 파일 **초안을 자동 생성**한다(모든 화면 `STATUS=PENDING`).
3. **그 회차는 리뷰를 수행하지 않고 종료**한다. (사용자가 목록을 검토·수정할 수 있도록)
4. 채팅에는 "화면 목록 초안을 생성했습니다. 검토 후 다음 루프부터 리뷰가 시작됩니다."와 함께
   생성된 화면 개수 및 스택 분포를 요약한다.

상태 파일이 **있으면** 단계 1로 진행한다.

---

## 단계 1. 리뷰 대상 선택 (상태 머신)

상태 값 정의:
- `PENDING` : 리뷰 대기 (선택 대상)
- `IN_REVIEW` : 리뷰 진행 중 (건너뜀)
- `DONE` : 리뷰 완료 (건너뜀, 결과는 `RESULT` 열로 구분)
- `BLOCKED` : 리뷰 불가 (건너뜀)

선택 규칙:
1. 위에서부터 **첫 번째 `PENDING`** 화면 1개를 선택한다.
2. **고아 IN_REVIEW 회수**: `IN_REVIEW`인데 `UPDATED_AT`이 60분 이상 지났고 해당 보고서 파일이 없으면,
   이전 회차가 중단된 것으로 보고 `PENDING`으로 되돌린 뒤 선택 후보로 삼는다.
3. 선택한 화면의 상태를 즉시 `IN_REVIEW`로, `UPDATED_AT`을 현재 시각으로 갱신한다.

**조기 종료(루프 no-op)**:
- 선택 가능한 `PENDING`이 하나도 없으면, **리뷰를 수행하지 않고** 다음을 출력한 뒤 종료한다.
  - 전체/`DONE`/`NEEDS_FIX`(RESULT)/`BLOCKED` 화면 수 요약
  - "모든 화면 리뷰가 완료되었습니다. 루프를 중지해도 됩니다." 안내

---

## 단계 2. 스택 감지 및 계층 매핑

선택한 화면이 속한 스택을 코드 근거로 감지하고, 리뷰 계층 용어를 자동 적응시킨다.

| 일반 계층 | 웹 스택 매핑 | 데스크톱 스택 매핑(Qt/Delphi 등) | 비고 |
|---|---|---|---|
| 진입/내비게이션 | Route, URL | 탭/윈도우 등록, 메뉴, 액션 시그널 | 진입 경로 추적 |
| 뷰/컴포넌트 | 프론트 컴포넌트 트리 | 위젯/폼 트리, .ui/폼 정의 | UI 구조 |
| 상태/입력 | store/state, 폼 검증 | 위젯 상태, 입력 검증/정규화 | 동일 관점 |
| 데이터 호출 | API client, 요청/응답 DTO | 서비스 호출, 시그널/슬롯, IPC/JSON | 경계 추적 |
| 컨트롤러/핸들러 | Controller/Handler | 이벤트 핸들러, 슬롯, 콜백 | 진입 로직 |
| 비즈니스 로직 | Service | Service/Manager/Engine | 동일 관점 |
| 데이터 접근 | Repository/Mapper/SQL | DAO, 쿼리, 파일/DB 접근 | 동일 관점 |

- 해당 스택에 존재하지 않는 계층은 발견 사항이 아니라 **"해당 없음(사유)"**으로 표기한다.
- 스택을 단정할 수 없으면 `확인 불가(경로)`로 남긴다.

---

## 단계 3. 리뷰 수행 (필수 확인 항목)

아래 항목을 화면의 스택에 맞춰 확인한다(해당 없는 항목은 "해당 없음"):

1. 화면 진입 경로와 내비게이션(라우팅/탭 등록/메뉴)
2. 뷰·컴포넌트(위젯/폼) 구조
3. 상태 관리, 폼 검증, 입력값 정규화
4. 데이터 호출 경로, 요청 DTO, 응답 DTO(또는 IPC/JSON 페이로드)
5. 컨트롤러 / 이벤트 핸들러 / 슬롯
6. 서비스 / 비즈니스 로직
7. 데이터 접근(Repository / Mapper / Query / SQL / 파일)
8. 인증, 권한, 세션, 토큰
9. 개인정보·민감정보·로그 노출
10. 예외 처리와 오류 메시지
11. 트랜잭션, 동시성(스레드/시그널), 데이터 정합성
12. 성능, N+1, 캐싱, 페이징, UI 블로킹(메인 스레드 차단)
13. 테스트 코드와 누락 테스트
14. 빌드·린트·테스트 검증 명령 (읽기 전용/로컬 실행만, 결과를 보고서에 기록)

검증 명령은 **로컬 빌드/린트/단위 테스트까지만** 실행한다.
외부 API 호출, DB 마이그레이션, 운영 데이터 변경은 실행하지 않는다.

---

## 단계 4. 보고서 작성

`docs/reviews/screens/{SCREEN_ID}-{SCREEN_NAME}.md`에 아래 템플릿으로 작성한다.
- `{SCREEN_NAME}`은 파일시스템 안전 슬러그로 변환한다(공백→`-`, 경로문자 제거).
- 보고서 폴더가 없으면 생성한다.

---

## 단계 5. 상태 갱신

리뷰와 보고서 작성이 끝나면 `docs/screen-review-targets.md`에서 해당 화면 행을 갱신한다.
- `STATUS` = `DONE`(리뷰 완료) 또는 `BLOCKED`(근거 부족·환경 미비로 리뷰 불가)
- `RESULT` = `PASS` / `NEEDS_FIX` / `BLOCKED` (보고서 1번 최종 판정과 일치)
- `REVIEW_FILE` = 생성한 보고서 경로
- `UPDATED_AT` = 현재 시각
- 채팅에는 변경 전/후 상태와 보고서 경로를 한 줄로 요약한다.
  (자동 루프이므로 상태 변경은 즉시 적용하되 변경 내역을 반드시 로그로 남긴다.)

그 회차는 여기서 종료한다(다음 화면은 다음 루프에서).

---

## 근거 형식 (필수)

- 모든 코드 근거는 `파일경로:시작라인-끝라인`으로 표시한다.
- 라인 번호를 확인할 수 없으면 `확인 불가(파일경로)`.
- 정의가 없으면 `찾지 못함(검색어 또는 파일경로)`.
- 주석만 있고 구현이 없으면 `주석만 존재, 구현 확인 불가`.

## 금지 사항

- 1차 리뷰에서는 **소스 코드를 수정하지 않는다**. (문서 = 상태 파일·리뷰 보고서만 생성·수정 가능)
- 파일 삭제, 커밋, push, 배포 명령을 실행하지 않는다.
- DB 마이그레이션, 운영 데이터 변경, 외부 API 호출을 실행하지 않는다.
- 민감정보, 토큰, 비밀번호, 개인정보, 접속정보를 출력하지 않는다.
- 찾지 못한 파일·메소드·테이블·API를 임의로 생성하지 않는다.

```markdown
# 화면 리뷰 대상 목록

- 상태값: PENDING / IN_REVIEW / DONE / BLOCKED
- 결과값(RESULT): PASS / NEEDS_FIX / BLOCKED / (미정)

| SCREEN_ID | SCREEN_NAME | STACK | ENTRY(진입점/주요 경로) | STATUS | RESULT | REVIEW_FILE | UPDATED_AT | NOTES |
|---|---|---|---|---|---|---|---|---|
| S001 | 대시보드 | C++/Qt | 진입점 파일:라인 | PENDING |  |  |  |  |
| S002 | 포트폴리오 | C++/Qt | 진입점 파일:라인 | PENDING |  |  |  |  |
```
